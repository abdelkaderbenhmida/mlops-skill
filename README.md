# Attest — Model Risk & AI Compliance Platform

> **Evidence-generating model governance for regulated credit decisioning.**
> Enterprise rewrite of the original "MLOps skills showcase": same stack, re-scoped so every
> component satisfies a requirement someone is legally or financially accountable for
> (EU AI Act Annex III, ECOA/Reg B, SR 11-7).
>
> **Scope**: 100% MLOps — data/model lifecycle, feature store, tuning, explainability,
> fairness, serving, monitoring, champion/challenger. **Excluded**: Kubernetes,
> Terraform/Ansible, Vault, generic infra monitoring.
>
> Full product spec: [`mlops-full-mlops-skills-project.md`](mlops-full-mlops-skills-project.md)

## What Attest is

The model-validation document becomes a **build artifact**. Validation evidence (data
lineage, performance, fairness, explainability, stability, model card) is generated by the
pipeline, versioned with the model, and regenerated automatically at every promotion — the
**Evidence Pack**. Every production decision is written to an append-only, hash-chained
**Decision Ledger**, and SHAP contributions are compiled into regulator-acceptable
**adverse-action reason codes**.

Four components make this an enterprise platform rather than a portfolio piece:

1. **Decision Ledger** — write-once, hash-chained, replayable record of every decision
   (the product's moat).
2. **Reason Code Engine** — SHAP → human-readable reason codes, versioned with the model.
3. **Fairness Gate (tiered)** — Green/Amber/Red thresholds anchored on the four-fifths rule;
   Red blocks promotion, Amber requires recorded sign-off.
4. **Human Oversight Console** — AI Act Art. 14 oversight queue with typed-justification
   overrides, surfaced as a monitoring signal.

**One architectural rule: no model reaches Production without a generated Evidence Pack and
a recorded human approval. Automatic promotion to Production is impossible.**

## Architecture Overview

```
Loan Origination System (system of engagement)
        │ scoring request
        ▼
Decision Service (BentoML)
   features (Feast online) → model → score → policy rules → outcome
        │ → SHAP → reason codes
        │ every decision
        ▼
DECISION LEDGER (append-only · hash-chained · 7-year retention)
        │                    │                       │
        ▼                    ▼                       ▼
Evidently             Human Oversight        Audit / Regulator
drift + perf          Console                export API
        │
        │ drift breach or scheduled review
        ▼
Retraining pipeline (ZenML)
   GE → DVC → Feast → train → Optuna → Deepchecks
   → Fairlearn gate → SHAP → Model Card → Registry
        │
        │ Staging, never auto-Production
        ▼
Evidence Pack generated + MRM approval required
```

## Quick Start

### 1. Install Dependencies

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### 2. Generate Synthetic Data

```bash
python data/raw/generate_churn_data.py
# Outputs: data/raw/dataset.csv (~7000 rows, sensitive attribute: gender)
```

> The bundled demo dataset is a churn-style synthetic file used to exercise the platform's
> control pipeline. The platform's target use case is consumer credit decisioning; the
> control components (ledger, fairness gate, reason codes, evidence pack) are
> use-case-agnostic.

### 3. Run Data Validation — Input Data Contract (Great Expectations)

```bash
great_expectations checkpoint run dataset_checkpoint
```

### 4. Run DVC Pipeline

```bash
dvc repro
```

### 5. Train + Track with MLflow

```bash
python -m src.models.train --register --run-name demo_model
# Or via ZenML:
python -m pipelines.training_pipeline
```

### 6. Hyperparameter Tuning (Optuna)

```bash
python -m src.models.tune --trials 50
# Or via ZenML:
python -m pipelines.tuning_pipeline
```

### 7. Explainability (SHAP)

```bash
python -m src.models.explain
# Generates: reports/shap_summary.png, per-decision SHAP for reason codes
```

### 8. Fairness Audit — Tiered Gate (Fairlearn)

```bash
python -m src.models.fairness_check
# Generates: reports/fairness_report.json, reports/fairness_selection_rate.png
# Classifies result Green / Amber / Red (four-fifths-rule anchored thresholds)
```

### 9. Promotion Gates

```bash
python -m src.models.promote
# Checks: performance, beats production, Deepchecks, Fairness gate,
#         reason-code coverage, evidence pack + approval record
# On success: moves model to MLflow Production stage + generates model card
```

### 10. Serve with BentoML

```bash
bentoml serve src.serving.bento_service:svc
# POST /predict  → {prediction, adverse_action_codes}
# POST /explain  → {expected_value, shap_values}  (waterfall for the Oversight Console)
# Every decision is written to the Decision Ledger
```

### 11. Champion/Challenger Routing

```bash
python -m src.serving.champion_challenger --requests 1000
# Routes ~10% to challenger (shadow-mode-first), logs every decision to the ledger
```

### 12. Drift Monitoring (Evidently)

```bash
python -m src.monitoring.drift_report --drift-strength 0.5
# Generates: monitoring/reports/drift_report.html
# Post-market monitoring evidence (SR 11-7 / AI Act Art. 72)
```

### 13. Automated Retraining Trigger

```bash
python -m src.monitoring.retraining_trigger --dry-run
# Triggers ZenML retraining_pipeline when drift_score > 0.3
# Promotion to Staging only — Production requires evidence pack + human approval
```

## Platform Capabilities

| Domain | Tool | Role in Attest |
|--------|------|------|
| Data Versioning | DVC | Regulatory reproducibility — dataset hash linked to every run |
| Data Quality | Great Expectations | Input data contract; failures logged as control failures |
| Feature Store | Feast (offline + online) | Point-in-time correctness prevents target leakage |
| ML Orchestration | ZenML (or Metaflow, picked once) | Versioned, cacheable pipelines |
| Experiment Tracking | MLflow | System of record: decision → model → run → data hash → commit |
| Hyperparameter Tuning | Optuna (Bayesian) | Automated search, logged as child runs |
| Model Registry | MLflow Registry | Staging/Production lifecycle with approval records |
| Model Validation | Deepchecks | Automated validation suite replacing manual checklist items |
| Explainability | SHAP (global + local) | Input to the Reason Code Engine (adverse action codes) |
| Fairness | Fairlearn (tiered gate) | **Core deliverable** — Green/Amber/Red with sign-off |
| Decision Ledger | Append-only hash-chained store | Immutable decision record + replay verification (moat) |
| Reason Codes | Mapping layer SHAP → text | Regulator-acceptable adverse action reasons, top-4 |
| Human Oversight | Oversight console | Art. 14 oversight; overrides logged and monitored |
| Model Serving | BentoML (predict + explain) | Decision service writing every decision to the ledger |
| Champion/Challenger | Custom router + ledger logging | Controlled change management, shadow-mode-first |
| Production Monitoring | Evidently (3 drift types) + PSI | Post-market monitoring evidence |
| Model Cards | Auto-generated (MLflow + Fairlearn) | Regulator-facing documentation in the Evidence Pack |
| Automated Retraining | Drift-triggered ZenML pipeline | Staging-only promotion; MRM approval for Production |
| ~~AutoML~~ | — | **Cut** — ungovernable ensembles in regulated credit |
| ~~LIME~~ | — | **Cut** — SHAP suffices; no regulatory upside to reconciling two explainers |
| ~~ONNX~~ | — | **Deferred** — no latency need; conversion-fidelity risk |
| ~~Kubernetes/Terraform/Vault~~ | — | Out of scope (DevOps/DevSecOps) |

## Configuration

Key thresholds in `src/config.py` (reference values for the demo):

```python
FAIRNESS_DP_THRESHOLD = 0.1      # Demographic parity difference (hard gate)
DRIFT_THRESHOLD = 0.3            # Drift score trigger
F1_PROMOTION_THRESHOLD = 0.5     # Minimum F1 for promotion
CHALLENGER_RATIO = 0.1           # 10% traffic to challenger
```

> The product spec ([§8.3](mlops-full-mlops-skills-project.md)) defines the enterprise
> **tiered fairness gate** (Green / Amber / Red, four-fifths-rule anchored) that supersedes
> the single binary threshold as the production control.

## Evidence Pack

Generated automatically at each promotion, versioned and immutable:

```
evidence/{model_name}/{version}/
├── model_card.md              # purpose, limits, intended use, out-of-scope use
├── data_lineage.json          # DVC hashes, Feast feature views, date ranges
├── training_report.html       # hyperparameters, Optuna search space + trials
├── performance.json           # AUC, KS, Gini, PSI, by segment and overall
├── fairness_report.html       # Fairlearn metrics, gate result
├── explainability_report.html # global SHAP, per-decile SHAP
├── stability_report.html      # PSI vs. development sample, vintage backtest
├── deepchecks_suite.html      # data + model validation suite results
├── reason_code_mapping.csv    # feature → reason text, with coverage assertion
├── approvals.json             # who approved, when, on what basis
└── manifest.json              # SHA-256 of every file above, signed
```
